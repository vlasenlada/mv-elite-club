# Аудит рабочих сценариев M&V Elite Club

Дата: 16.11.2026.

Учебный цикл от регистрации до оценки подтверждён для индивидуального и
группового форматов. Проверки выполнены на чистых базах в памяти. Для браузера
запускался отдельный временный сервер 127.0.0.1:8765 с вымышленными пользователями,
работами и тестовыми тарифами. Он остановлен, настоящие аккаунты не использовались.
Это функциональная готовность к контролируемому пилоту; настройки локального
окружения пока не готовы для публичного запуска в интернете.

## Результаты по сценариям

| Сценарий | Результат и проверка |
|---|---|
| Регистрация | HTTP POST создаёт только ученика; подмена role, is_staff, is_superuser не даёт привилегий. После регистрации открывается кабинет или безопасный выбранный курс. |
| Вход и выход | Проверены верный/неверный пароль, кабинет каждой роли, безопасный next, отказ от внешнего перенаправления, выход только POST. |
| Разграничение ролей | Ученик не может управлять заявками или оценками, преподаватель не видит чужие работы, чужие группы и ссылки закрыты. Проверены прямые запросы. |
| CSRF | Новые сквозные тесты используют Client(enforce_csrf_checks=True): формы проходят с токеном, запрос без токена отклоняется. |
| Каталог | Семь курсов, включая исторический; две карточки форматов, разные тарифы, пустые тарифы, фильтры предмета и классов. |
| Заявка | Формат сохраняется, виден ученику и администратору, повторный POST другого формата не меняет выбор и не создаёт дубль. Подтверждение/отклонение и ограничения неактивных заявок покрыты тестами. |
| Индивидуальный цикл | Регистрация → заявка → подтверждение → преподаватель → занятие → ссылка → ответ → оценка и комментарий в кабинете. |
| Статусы и расписание | Ссылки доступны только своим ученикам при допустимых статусах. Старые тесты проверяют пересечения ученика/преподавателя, редактирование, переносы, замены, отменённые уроки и Admin. |
| Групповой цикл | Два ученика подают и получают подтверждение групповых заявок; администратор создаёт группу с несколькими участниками одним POST; преподаватель создаёт один общий урок. |
| Вместимость | Произвольные положительные значения, счётчик мест, переполнение обычным и пакетным добавлением, запрет уменьшения/очистки установленного лимита. |
| Посещаемость | На общем уроке две отдельные записи, преподаватель сохраняет разные статусы, ученик видит только свою запись. |
| Групповые работы | Одна общая задача, два отдельных ответа, разные оценки и комментарии; чужие ответы и результаты не раскрываются. |
| Изменение состава | Выход освобождает место и закрывает будущие подключения/новые ответы; проведённые уроки и учебные записи сохраняются. Ранее полученную работу можно проверить и после выхода. |
| Преподаватели | Назначение на конкретную заявку, замены и смена преподавателя с проверкой расписания/домашних работ сохраняют прежние ограничения. |

## Обнаруженные и исправленные ошибки

1. **Вход направлял все роли на главную.** Добавлен SchoolLoginView с выбором
   кабинета по роли. Безопасный next имеет приоритет. Регистрация без next
   теперь тоже направляет ученика в кабинет; внешний next не принимается.
2. **Индивидуальную учебную историю можно было перепривязать через Admin.**
   В отличие от групповой заявки, смена ученика или курса индивидуальной заявки
   с уроками проходила проверку. Теперь обе истории защищены одинаково;
   форма показывает ошибку и сохраняет прежние связи и оценки.
3. **Работа к будущему групповому уроку исчезала из кабинетов после выхода.**
   Данные оставались в базе, но выборки их скрывали, а преподаватель получал 404
   при проверке. Теперь учитывается членство на дату урока либо на момент
   получения ответа. Собственная оценка остаётся видна, преподаватель урока
   может закончить проверку. Доступ к встрече/новым ответам не возвращается.
   Неправомерный ответ пользователя без истории членства по-прежнему скрыт.
   Выборка использует Exists и сохраняет интерфейс QuerySet прежних проверок.
4. **Неверная оценка отклонялась молча.** При значениях вне 0–100, пустом или
   нечисловом значении преподаватель получает сообщение. Старая оценка и
   комментарий не перезаписываются. Успешное сохранение также подтверждается.
5. **Кнопка результата вела на отсутствующий якорь.** Добавлен id=my-progress
   к существующему разделу результатов; структура и оформление не изменены.
6. **Ссылка на группы плохо читалась в бордовом блоке администратора.**
   Для этой ссылки использован существующий кремовый цвет. Версия CSS в ссылке
   обновлена, чтобы браузер получил исправление вместо прежнего кэша.
7. **Заявку можно было переключить на групповой формат с сохранённым
   индивидуальным преподавателем.** До появления уроков форма это допускала,
   если сам преподаватель не менялся. Теперь несовместимое изменение
   отклоняется с понятным сообщением; прежняя заявка остаётся без изменений.

## Визуальная и ручная проверка

- В браузере на ширине 390 px проверены вход/выход, главная, каталог, два тарифа,
  кабинет ученика, расписание, форма ответа, кабинет преподавателя и выставление
  оценки с комментарием, журнал группы и личная посещаемость.
- Панель администратора и форма Django Admin для группы проверены на телефоне:
  поле вместимости и кнопки сохранения доступны. Широкие таблицы прокручиваются
  внутри блоков, а не расширяют всю страницу.
- Панель администратора дополнительно проверена на 820 и 1280 px.
- Горизонтального переполнения страницы в проверенных состояниях нет.
- Исправленный контраст ссылки подтверждён в браузере: кремовый текст
  на бордовом фоне. Карточки курсов и основной style.css не перекрашивались.
- Это эмуляция размеров браузера. Физические iPhone/Android, Safari,
  экранная клавиатура и вспомогательные технологии отдельно не проверялись.

## Автоматические проверки

- **184 теста прошли**: все прежние 170 и 14 новых тестовых методов
  users/test_school_workflows.py. Внутри методов также есть сценарии по ролям
  и разные недопустимые значения; они не считаются отдельными тестами.
- Обычный Django system check: **0 issues**.
- makemigrations --check --dry-run: **No changes detected**.
- Новые миграции не создавались и не применялись.
- git diff --check: ошибок пробелов нет; Git сообщает лишь о преобразовании
  окончаний строк LF/CRLF в нескольких уже изменённых файлах.
- Настоящая база дополнительно открывалась только mode=ro для проверки:
  integrity_check = ok, foreign_key_check без нарушений, семь опубликованных

- В настоящей базе оба тарифа пока пусты у всех семи курсов. Тестовые суммы
  использовались исключительно в памяти и не записывались в db.sqlite3.
- Контрольные суммы 25 защищённых файлов, включая db.sqlite3, .env,
  основной CSS и все существовавшие миграции, совпали с началом аудита.
  Резервные копии не изменялись. Commit и push не выполнялись.

## Что остаётся перед публичным запуском

**Приоритет 0 — окружение сервера.** Проверка Django с deployment checks
выявила 1 ошибку и 5 предупреждений:

| Код | Наблюдение |
|---|---|
| mail.E001 | MAILERS использует console backend: реальная почта не отправляется. |
| security.W018 | Включён DEBUG. |
| security.W008 | Не включено перенаправление на HTTPS. |
| security.W012 | SESSION_COOKIE_SECURE не включён. |
| security.W016 | CSRF_COOKIE_SECURE не включён. |
| security.W004 | Не настроен HSTS. |

Это локальная конфигурация разработки. Не менять её вслепую для HTTP localhost:
подготовить отдельные настройки боевого домена, HTTPS и прокси, секреты вне Git,
реальную почту и повторить deployment checks в том окружении. HSTS включать
после проверки корректного HTTPS. В рамках аудита эти настройки не изменялись.

**Приоритет 1 — организационная готовность.** Владелец задаёт два тарифа
через Admin и заполняет настоящие контакты вместо текста-заглушки.
Провести один контролируемый урок с преподавателем и учеником: проверить
реальное приглашение Zoom/Meet, звук, камеру и поведение ссылки вне сайта.
Проверка сайта подтверждает права и редирект, но не работу стороннего сервиса.

**Приоритет 1 — эксплуатация.** Проверить боевые резервные копии и согласованный
процесс восстановления, журналирование ошибок и порядок восстановления
доступа ученику. Самостоятельного восстановления пароля в публичных маршрутах
сейчас нет; его добавление — отдельная задача. Восстановление базы не выполнялось.

**Приоритет 2 — отдельные испытания.** Выполнить проверки на физических
телефонах и согласованную нагрузочную проверку, особенно одновременного
бронирования времени/последнего места. Текущие тесты подтверждают правила
последовательных HTTP-запросов и серверную валидацию; параллельная нагрузка
нескольких администраторов в этом аудите не моделировалась.

**Существующие ограничения процесса.** Повторная заявка после отклонения,
изменение уже выбранного формата и переход из индивидуального обучения в
группу решаются администратором: автоматической конвертации учебной истории
нет. Это предотвращает дублирование и потерю связей. Сами заявки доступны
в кабинете и Django Admin; автоматическая доставка уведомлений не подтверждена.
Окончание дедлайна сейчас носит информационный характер, отдельного запрета
поздних ответов нет — правило школы нужно согласовать отдельно.
